# DSH 导入：Agent 沙箱学习模式

这是本仓库自带的教学预设（DSH bundle），目的是**换一台机器、换一个 DSH 会话，也能原样接续这套教学**：教师人格、教学信条、实验红线、学生档案、当前「面试优先」模式和接续顺序都写在里面。

## 导入步骤

1. 在目标机器上把本仓库放到 DSH 的工作区（例如 `D:\learning\Learning\microVMprac`）。
2. 把 `dsh-preset/` 整个目录复制到 DSH 工作区的 bundle 目录并改名：

   ```powershell
   # Windows
   Copy-Item -Recurse -Force "microVMprac\dsh-preset" "$HOME\.dsh-bundles\study-mode"
   ```

   ```bash
   # Linux / WSL
   cp -r microVMprac/dsh-preset ~/.dsh-bundles/study-mode
   ```

   本机当前使用的 bundle 位置是 `D:\learning\Learning\.dsh-bundles\study-mode\`，两份内容应保持一致；改了其中一份记得同步另一份。

3. 重启 DSH，在预设（preset）选择里选 **「Agent 沙箱学习模式」**。
4. 新会话第一句话可以直接说「继续学习」，教师会按 persona 里的接续顺序先读：
   `AGENTS.md` → `04-AgentENV/学习记录.md` → `04-AgentENV/面试题库.md` → `04-AgentENV/源码索引.md`。

| 文件 | 作用 |

| `cordis.patch.yml` | 预设定义：persona 系统提示 + 工具插件清单 |

## 与仓库文档的分工

- **persona（本目录）**：教学方式、判据、红线、接续顺序。稳定，少改。
- **`AGENTS.md`**：给「读仓库的 agent」的同一套约定摘要，保证不导入 bundle 也能接续。
- **`04-AgentENV/学习记录.md`**：进度与接续点，每轮更新。
- **`04-AgentENV/面试题库.md`**：当前模式的题库、四段式模板、五个必深点。

改动 persona 时请同时更新本 README 的版本号与下表记录。

# 第二轮：能力导向评估（2026-11-17 生效）

> 本文件是**评估标准的唯一出处**。persona 里只放执行规则（禁止项、循环要求、记分板怎么记），表格与细则在这里。
> 第一轮（2026-10-23 — 2026-11-16）为广度覆盖，不计入本标准的分数。

## 0. 最终目标

> 面对一条沙箱操作链路，能**独立解释**它如何工作、**预测**条件变化后的行为；面对异常，能提出**可区分**的原因、选择证据缩小范围，并明确结论的**边界**。

评估同时看三样：**知识覆盖面**、**理解深度**、**实际验证能力**。只看答题正确率，或只看做了多少实验，都不合格。

## 1. 覆盖面：七个领域，各有必须独立完成的任务

| # | 领域 | 必须独立完成的任务 |
|---|---|---|
| D1 | 执行与虚拟化 | 解释物理 CPU／vCPU 线程／Guest 调度的关系；画出 `KVM_RUN` 与退出处理的分流 |
| D2 | 内存与地址空间 | 画清 GVA/GPA/HVA/HPA、memslot 与 EPT；解释跨进程读取、缺页与 COW |
| D3 | 存储与设备 IO | 从 Guest 文件读取追到后端再返回；区分 VirtIO／ublk／io_uring／OverlayBD 及各自完成点 |
| D4 | 创建、快照与恢复 | 追踪创建、就绪、暂停、捕获、持久化、恢复；指出一致性与外部状态的边界 |
| D5 | 网络与 envd 通信 | 追踪 Host → Guest 应用的请求与返回；区分网络连通／监听／健康／鉴权／命令执行结果 |
| D6 | 隔离与资源生命周期 | 说明虚拟化／namespace／cgroup／seccomp／降权各约束谁；判断资源何时可安全释放 |
| D7 | 性能与并发 | 正确定义 wall／CPU／吞吐／尾延迟；分析缓存、排队、阻塞、忙轮询及优化代价 |

两条附加约束：

- **不得互相抵消**：任何领域都不能用其他领域的高分补偿（含 D2 内存不得抵消 D5、D6）。
- **跨域案例**：至少 1 个横跨多域的案例（例：「快照恢复后网络不通」同时命中 D4+D5+D6）。只按单域打分会高估能力。

## 2. 深度：五项能力，各占 20%

| 能力 | 看什么表现 | 怎么测 |
|---|---|---|
| A 机制理解 | 能解释因果、成立条件与代价 | 闭卷画图；回答「为什么」「少这一步会怎样」 |
| B 链路与实现追踪 | 概念能落到进程、线程、接口、参数、返回值 | 取一段关键调用链，说明地址归属、数据位置、完成条件 |
| C 验证与证据判断 | 能设计验证方法、正确解释结果 | 先给预测，再选源码或实验，说明证据支持什么、不能证明什么 |
| D 问题提出与定位 | 能把异常变成具体问题、缩小范围 | 面对陌生故障，提出 ≥2 个可区分解释，按观测继续排查 |
| E 迁移与保持 | 换条件、隔时间后仍能推理 | 改缓存／线程数／故障位置／恢复方式，再次解释行为 |

「问题提出」单列，因为研发不只是接别人给的故障题。合格的问题长这样：

> 如果快照层已发布但父层引用没保存完整，恢复会在哪个阶段失败？现有的「成功」响应能否覆盖这个风险？

而不是「这个方案有没有问题」。

## 3. 打分：0—4 分，五项能力同一套标准

| 分 | 判定 |
|---|---|
| 0 | 没有形成解释，或核心结论错误且无法修正 |
| 1 | 能认出术语与组件，但因果关系不清 |
| 2 | 在提示下能完成主要推理，仍有关键遗漏 |
| 3 | 能独立解释或验证，结论与证据匹配，并说明主要边界 |
| 4 | 换条件后仍能推理；能识别反例、比较替代解释、主动修正模型 |

**3 分为主要目标**；4 分表示该题更深，不等于「能带人」或「能处理生产事故」。

分数用来读**能力分布**，不是读总分：

```text
A 机制理解        3
B 链路与追踪      3
C 验证与证据      2   ← 下一阶段重点
D 问题提出与定位  3
E 迁移与保持      2   ← 需要延迟复习
```

## 4. 「能定位问题」的五项检查（每个故障案例都过一遍）

1. **问题是否具体**：说清预期行为、实际行为、发生范围、已知条件。
2. **解释是否可区分**：≥2 个具体原因，并写出各自预期的不同现象。
3. **观测是否有效**：所选观测真能区分这些原因，而不是重复收集同类信息。
4. **结论是否克制**：证据不足时保留候选，不强行宣布根因。
5. **后续是否合理**：根据结果更新判断，选下一条观测或最小验证。

**判定要点**：不能把「猜中 envd 没启动」直接算定位成功。**猜错初始原因、但通过有效证据排除它并最终找到问题，反而体现定位能力。**

## 5. 验收：三类任务，不能只考一种

| 形式 | 范围 | 主要检查 |
|---|---|---|
| 闭卷机制与变化题 | 七个领域各抽一个场景 | 覆盖面、因果、条件迁移 |
| 源码或实验任务 | ≥2 个不同领域，其中一个是 D5 或 D4 | 独立找证据、操作验证、解释输出 |
| 陌生故障案例 | ≥3 个，覆盖不同链路（含 1 个跨域） | 提问、假设、观测选择、修正判断 |

其中**至少一次安排在相关主题结束后 7—14 天**，检查保持情况。允许查接口细节；涉及基本结构与因果关系时必须闭卷。

证据类型必须分别标注：**纸面推演 / 本地简化实验 / 真实 microVM 实验**。三者都有价值，不能互相冒充。

## 6. 达成条件（同时满足，不要求全对）

- **覆盖面**：七个领域均有评估记录，没有未触及的领域。
- **能力水平**：五项能力在**多次**任务中稳定在 3 分左右，不能靠一道熟题判定。
- **薄弱补齐**：D5（网络/envd）与 D4（创建启动）各完成至少一次独立链路解释 + 一次验证任务。
- **迁移保持**：延迟测试中能重建主要机制；遗漏细节能自行查证补齐。
- **边界意识**：主动区分事实／假设／待验证项，不把局部成功当整条链成功。

**只记学习投入、不计能力分**：课程数量、笔记页数、读代码行数、「感觉听懂了」。

## 8. 教学循环

```text
问题 → 模型 → 预测 → 证据 → 迁移
```

| 步 | 要求 | 硬约束（否则等于缩水） |
|---|---|---|
| 问题 | 从具体现象出发，不从「今天学 X」出发 | 写成「预期／实际／范围／已知条件」 |
| 模型 | 先画自己的解释，再看资料 | 图上每个箭头标：地址属于谁、字节此刻在哪、这步的完成点；缺一项算没画完 |
| 预测 | 在看结果之前写下来 | 四段：数值或方向 + 量级 + 理由 + 若偏差 10 倍最可能是什么 |
| 证据 | 最少但足够 | 能指到 `file:line`，或自己跑出的命令输出；并写「排除了什么、没排除什么」 |
| 迁移 | 换条件；隔 7—14 天重建 | 迁移题**由教师出**，自己出题会避开盲区 |

**两档循环**（防止流程表演）：

| 档 | 时长 | 内容 | 用在 |
|---|---|---|---|
| 最小循环 | 30 min | 一个问题 → 一张图（三必标）→ 一个预测 → 一个证据 → 一句「何时变坏」 | 大多数主题 |
| 完整循环 | 90—120 min | 追加：写代码／跑实验、迁移题、错误记录、反例 | 五个必深点、D4/D5/D6 |

## 9. AI 与学生的分工

| 环节 | AI 负责 | 学生负责 |
|---|---|---|
| 找入口 | 定位调用链、解释陌生语法 | 确定要解决的问题 |
| 建模型 | 指出图中遗漏的角色与边界 | **先画自己的版本** |
| 验证 | 设计小实验、找反例、出迁移题 | **先预测，再解释结果** |
| 复习 | 提供变化场景与追问 | 脱离材料回答并说明理由 |

**教师禁止**：给出可直接运行的完整脚本；替学生归纳「这段代码说明了什么」；在学生预测之前公布结果。

## 10. 材料冻结

在有三个自测数字之前，不生产新 PPT、新动画、新图解。理由：材料变丰富不等于理解变深入。
