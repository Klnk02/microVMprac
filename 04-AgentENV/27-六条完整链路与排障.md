# 第27课：六条完整链路与排障

2026-11-16 第一轮综合复习。整合第01—26课既有笔记，AgentENV基线仍为 `9f62cbe07cebfecf416dc9bdcf497e2a97687644`。本轮没有新增逐行审计或真实VM观测。读路径为此前选择的VirtIO/ublk/OverlayBD模型；实现模式、缓存和版本可改变细节，不按箭头数复制次数。配套FC内存映射/共享缓存模式仍待核验。

## 场景与读图规则

在节点A创建实例，执行Guest命令读文件，保存快照S，销毁旧运行时，再从S恢复。不是所有系统都按同一API保留/销毁暂停运行时，因此将“暂停”“快照”“销毁”“从S恢复”分开描述。

每条链固定检查：谁执行、地址/字节在哪里、完成到哪层。Guest进程不等于宿主普通子进程，server对象不等于Guest envd，KVM处理退出不等于KVM_RUN返回用户态。

## 1. 创建

客户端 → 可选gateway/scheduler选节点 → 节点server/orchestrator → 准备网络/磁盘/FC → 配置并启动Guest → envd响应就绪检查。

冷启动从内核/rootfs启动；模板快照恢复要装载既有状态，两者不能合为一个必经顺序。取到池条目仅省掉对应准备。创建就绪只说明接口约定的准备/健康检查通过，不保证所有业务依赖或RAM页都已准备。失败按已取得资源回收。

详见[08](08-启动与就绪.md)、[25](25-多节点与资源池.md)。

## 2. exec

客户端 → gateway按ID查归属（多节点模式） → 节点server的envd客户端 → Guest envd → Guest内核启动/管理命令进程 → 输出事件与结束结果返回。

Start表示启动，输出不等于结束；End/退出码按协议判断。超时只说明没按期拿到结果，实际命令可能未到、执行中或已完成。不能据此盲目重试有副作用的命令。

详见[09](09-命令执行与事件流.md)、[23](23-失败与恢复.md)。

## 3. Guest文件读

Guest用户pread → Guest VFS/文件系统/缓存 → 若数据缓存未命中，VirtIO块驱动发布描述符链到avail → 必要时MMIO通知 → FC设备后端 → Host ublk → daemon/OverlayBD → 后端字节。

完成沿反方向回传：daemon报告结果 → Host块请求完成 → FC发布used与设备状态 → Guest驱动/FS处理 → 用户buffer填好，pread按实际结果返回。

FETCH CQE仅领取任务，后端READ CQE需查字节数/错误，used需配设备状态，pread返回4096才表明本次用户buffer获得4096字节。实际字节不装在通知里；普通磁盘payload通常不经server中转。Guest缓存命中可免本次VirtIO数据读取，Host/后端缓存命中可免相应取数。

详见[06](06-VirtIO描述符队列与通知.md)、[12](12-ublk与存储daemon.md)。

## 4. pause与快照捕获

节点server发宿主控制请求 → FC协调暂停vCPU和快照相关设备活动 → 获得稳定状态及相关修改记录 → 配套保存VM状态、磁盘视图与RAM层 → 完整发布。

RAM捕获分支：范围中的FC HVA + 目标PID → server调用process_vm_readv → server本地buffer → entry/chunk/writer保存payload和逻辑索引。先有范围描述不代表已有字节。CPU与VMM设备写入均需覆盖计脏，记录不冻结内容。暂停确认、字节读取、层格式完成、配套发布与持久化分别判断。

详见[14](14-快照状态与一致性.md)、[16](16-pause跨进程读取.md)、[17](17-chunk写出与快照封存.md)。

## 5. resume

原地resume：旧运行时仍在，按协议让其继续。下列是从快照重建：取得S的配套材料及父层 → 节点本地准备运行资源 → FC装载VM状态并关联RAM后端 → 补设备配置 → resume → envd就绪检查。

后续普通访存：Guest GVA→GPA→HPA。所需Host后备页尚未准备时，可涉及Host内存镜像ublk/OverlayBD取数，不要求Guest先发布VirtIO磁盘请求。恢复过程不应依赖已退出旧FC的PID/HVA；旧HVA只在旧进程的原映射中有意义，重建需恢复材料和新运行时的映射。恢复不等于全部页驻留，也不回滚外部连接/事务。

详见[18](18-从快照恢复.md)、[26](26-模板持久化与fork.md)。

## 6. 销毁

节点server推进停止状态 → 协调停止实际使用者和相关后台工作 → 确认底层IO不再访问对应资源 → 释放设备/网络/运行时等使用权 → 依所有者与池策略回收 → 核对残留与清理错误。

不能仅因业务超时就复用在途buffer；不能因FC退出就推断daemon/DMA已全部停用；共享设备仍被其他实例或任务使用时不可销毁。持久化快照与运行时资源分开，删除实例不自动表示其所有共享父层可删除。实际删除语义取决于接口与引用回收协议。

详见[21](21-资源拥有与回收.md)、[22](22-async与并发.md)。

## 用完成边界排障

| 观察到的事实 | 可以确认 | 仍需检查 |
|---|---|---|
| envd健康检查成功 | 该次服务检查成功 | 业务权限、文件、外部依赖 |
| FETCH CQE到达 | 块请求已交给daemon | 后端字节是否取得 |
| 后端READ完整成功 | 对应目的buffer已有字节 | FC/Guest上层是否处理 |
| vCPU暂停已确认 | Guest相关CPU执行已停 | 设备写入协调、快照捕获发布 |
| S在仓库完整发布 | 按相应契约可取得恢复材料 | 新节点兼容、权限与本地资源 |
| 原FC进程已退出 | 该进程不再执行 | 其他使用者、残留设备与共享引用 |

## 自测：从判断转向完整解释

2026-11-16 作答校准：server→VMM→Guest是创建主干，完整链还含准备磁盘/网络、配置与envd就绪；命令由Guest envd发起、Guest内核创建。恢复需要完整快照材料与父层，非旧进程指针。后端READ的目的buffer可在Host daemon中；Guest pread返回4096时，Guest用户buffer已取得4096字节，该buffer自身就在Guest RAM里，不是返回之后才从“buffer”进入Guest内存。不要把Host B、Guest缓存G、Guest用户U合为一个buffer。
