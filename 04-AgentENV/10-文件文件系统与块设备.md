# 第 10 课：文件、文件系统与块设备

2026-11-02 第一轮。本课讲通用机制与纸面示例；AgentENV 选中的具体磁盘后端分支尚未逐分支核对。

**要解决的问题**：Guest 打开 /workspace/a.txt 并调用 read(fd, ...) 怎样变成设备块读取？为什么文件写入返回不等于持久化？

## 一、角色放对位置

| 角色 | 在哪 | 负责什么 |
|---|---|---|
| 应用 | Guest 用户态 | 调用 `read()`，提供用户缓冲区 |
| VFS | Guest 内核 | 按文件描述符、文件偏移组织读写 |
| ext4 等文件系统 | Guest 内核 | 文件 ↔ 逻辑块映射、元数据 |
| Guest 页缓存 | Guest 内核内存 | 缓存文件页，命中可免设备 IO |
| 块层 | Guest 内核 | 合并、排队、调度块请求 |
| virtio-blk 驱动 | Guest 内核 | 把块请求变成 VirtIO 描述符与通知 |
| Firecracker 后端 | 宿主用户态 | 处理虚拟设备请求，访问宿主后端 |
| 宿主后端 | 宿主 | 镜像文件、块设备或 ublk 设备等 |

## 二、一次 4 KiB 读

假设 `/workspace/a.txt` 在 Guest 的 ext4 虚拟磁盘上，普通缓冲 IO，文件已打开，Guest 页缓存未命中：

```text
应用 read(fd, buf, 4096)
    ↓
VFS：查 inode，定位文件偏移 0
    ↓
ext4：文件内偏移 → 虚拟磁盘逻辑块
    ↓
页缓存未命中 → 块层生成块请求
    ↓
virtio-blk 驱动：描述符 + buffer + 通知
    ↓
Firecracker 虚拟设备处理
    ↓
宿主后端（镜像文件 / 块设备 / ublk）
    ↓
数据回到 Guest 页缓存与 buf，read 返回 4096
```

三个容易跳过的点：

1. **所需数据命中页缓存时不必为这些数据产生 VirtIO 读取**；路径解析、元数据、预读或其他并发操作仍可能产生 IO，不能推导整次调用绝无设备请求。
2. 把数据放进 Guest 缓冲区的是**设备与内核**，应用拿到的是拷贝后的字节。
3. **块设备按逻辑地址和长度服务，不认文件名**；`a.txt` 只存在于 Guest 文件系统语义里。

## 三、三种偏移不要混

| 偏移 | 属于谁 | 用途 |
|---|---|---|
| 文件偏移 | Guest 文件系统 | read 使用打开文件的当前位置；pread 的第四个参数显式指定偏移，read 第三个参数是字节数 |
| 设备逻辑偏移 / LBA | Guest 块设备 | 文件系统映射的结果；LBA 是逻辑块编号，必须结合块/扇区大小换算成字节 |
| 后端实际位置 | 宿主 | 镜像文件里的字节、层文件里的段、远端对象 |

纸面例子（课堂假设，不是磁盘取证）：文件大小 8 KiB，前后两段 4 KiB 分别映射到磁盘字节偏移 8 MiB、20 MiB。若按 512 字节扇区编号，分别是 16384、40960；若按 4 KiB 块编号，分别是 2048、5120。**文件内连续，设备上可以不连续**。不能只写一个 LBA 数字而省略单位，也不能认为文件偏移 0 就是设备偏移 0。

## 四、写路径：write 返回说明什么

```text
普通缓冲 write() → 数据进入 Guest 页缓存，标脏 → 通常可在回写前返回
    ↓（之后某个时刻，由内核回写）
块层 → VirtIO → Firecracker → 宿主后端 → 宿主页缓存/设备缓存 → 介质
```

普通缓冲 write 成功不保证数据持久化；它也可能因内存压力等阻塞，不能说必然立即返回。fsync/fdatasync 请求同步所需数据与元数据，虚拟化栈需正确传递和实现 flush/FUA 等语义。各层正确支持、遵守配置并报告成功时，才能依相应同步契约判断持久化；“还有缓存”本身不能否定 fsync 的目的或保证。O_SYNC/O_DSYNC、直接 IO、不同文件系统另有语义，不能套用这张缓冲写示意。

## 五、边界

- `/tmp` 可能是 tmpfs，根本没有块设备；不能把任意 Guest 文件都当虚拟磁盘文件。
- `O_DIRECT` 绕过页缓存，对齐与时序规则不同。
- 稀疏文件里的空洞不占实际块，读到零，但不是“显式零记录”。
- 块大小与扇区大小是两个概念（如文件系统块 4 KiB、扇区 512 B）。
- 原生内核接口使用负错误码；C/POSIX read 通常返回 -1 并设置 errno，例如 EIO。短读也可能发生，调用方必须检查返回字节数。

## 六、证据边界

本课是通用 Linux 机制与纸面推演；AgentENV 的 rootfs、ext4、OverlayBD 具体分支在 11、12 课展开，未逐分支核对。页缓存行为取决于内核版本与挂载选项，课上不假设特定缓存策略。

## 归档补充：两边缓存与暂停

```text
Guest 应用 buffer
    ↔ Guest 页缓存（Guest RAM）
    ↔ VirtIO 与 Firecracker 后端
    ↔ Host 页缓存（是否参与依后端/直接 IO 等配置）
    ↔ 存储设备缓存与介质
```

Guest 缓存与 Host 缓存是不同层。原地暂停再继续通常保留 RAM，但缓存可能随后被内核回收或失效，不能理解为其他程序随意覆盖。快照恢复时即使 Guest 认为缓存有效，承载 Guest RAM 的宿主页面也可能尚未驻留，访问时仍可触发内存镜像后端读取；这不等于 Guest 又发起了一次文件磁盘 VirtIO 读取。

参考：[read](https://man7.org/linux/man-pages/man2/read.2.html)、[write](https://man7.org/linux/man-pages/man2/write.2.html)、[fsync](https://man7.org/linux/man-pages/man2/fsync.2.html)。
