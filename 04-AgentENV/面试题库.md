# 沙箱方向面试题库（v0，面试优先模式）

2026-11-12 用户澄清：深刻理解知识是根本目标，面试优先用于安排重点和练习表达。规则三条：

1. 优先深入 5 个点（本文 A 区），其他主题先建整体认识，再按依赖、疑问与推理困难深入。
2. 先理解机制，再练习四段式表达：**结论 → 机制 → 边界/代价 → 一个数字或案例**。
3. 讲不出的地方先找缺失的前置概念与因果环节，用必要源码、C/C++ 伪代码、纸面推演或可复现观测补齐。实践经历按真实证据记录。

## 四段式答题模板

```text
结论：一句话给出判断（面试官先听到的是答案，不是铺垫）
机制：两句话讲清谁在哪一层做了什么（点名进程/内核/硬件层）
边界：一句半说清它挡不住什么、代价是什么
证据：一个数字、一次实测或一个真实故障（这是区分"背过"和"做过"的地方）
```

30 秒回答用于练习表达，不作为理解深度的单独判据。理解检查重在能解释原因、预测换条件后的结果、连接实际路径；机制理解、表达速度和实践证据分别反馈。

## A 区：五个必深点

### A1 地址空间：guest 里的指针，宿主怎么用

- 问：guest 的地址和宿主的地址是什么关系？你要读 guest 内存，怎么做？
- 30 秒要点：GVA→GPA 由 guest 页表翻译；GPA→HVA 是 VMM 进程的 mmap 登记；HVA→HPA 由宿主页表。读 guest 内存走 `process_vm_readv(目标 pid, 本地 iovec, 远程 iovec)`，两个 iovec 数组都在**调用者**内存里，远程地址按目标进程的 mm 解析。
- 追问链：① 为什么不直接读 `/proc/pid/mem`？② 短读怎么处理？③ 读到的页正在被 guest 写怎么办？
- 要补的证据：一次真实读取的字节数与耗时。

### A2 VM-Exit：guest 碰设备时发生什么

- 问：guest 访问设备为什么会回到宿主？MMIO 和 PIO 有什么区别？
- 30 秒要点：`ioctl(vcpufd, KVM_RUN)` 阻塞在非根模式跑 guest；碰到 VMCS 里配置要退出的事件就回来。MMIO 靠 EPT 故意不建映射，普通 `mov` 触发 EPT violation；PIO 的 `in/out` 本身是敏感指令。回到宿主后读 `kvm_run->exit_reason` 分流处理。
- 追问链：① 一次退出大概多少 ns？② VirtIO 怎么把 N 次退出压成 1 次？③ vCPU 线程被宿主信号打断和 VM-Exit 是一回事吗？
- 要补的证据：退出次数统计（`exit_mmio_write` 之类的计数器）。

### A3 快照与恢复：保存什么、为什么恢复后可能不通

- 问：microVM 快照要存哪几样东西？恢复后外部 TCP 连接还能用吗？
- 30 秒要点：寄存器/设备状态 + RAM + rootfs 三样配套；一致性靠先 pause 冻结再捕获。恢复只回滚 VM 内部，对端状态、宿主 conntrack/NAT、超时计时器都在"现在"。内存用只读 ublk + COW 按需加载，恢复成功不等于所有页已进宿主 RAM。
- 追问链：① 脏页列表为什么不能保证内容冻结？② 恢复后首次写一页发生什么？③ 为什么"请求内存量"不等于"读盘量"？
- 要补的证据：冷/热恢复的一次延迟对比。

### A4 隔离：一层一层说清各挡什么

- 问：你们沙箱怎么隔离？seccomp / namespace / cgroup 各挡什么？
- 30 秒要点：硬件虚拟化挡 guest↔host；namespace 改视图不改权限；cgroup 管用量，只记账就什么都挡不住；seccomp 是**线程级**白名单，拦的是 VMM 自己发出的宿主 syscall，拦不到 guest 内部的 syscall；VMM 被攻破后破坏力靠降权 + chroot + caps + LSM 收口。
- 追问链：① guest 里的 root 会被 seccomp 限制吗？② 没有 jailer 会缺哪几道？③ 升级 VMM 为什么可能被 seccomp 直接杀掉？
- 要补的证据：一次真实 VMM 进程的线程数、各线程 Seccomp 值、cgroup 限额是否真的设置了。

### A5 性能度量：数字怎么读

- 问：沙箱冷启动 3 秒，你怎么查？
- 30 秒要点：先分段（拉镜像/建盘/起 VMM/等 envd 就绪/首条命令完成），每段给 wall 和 CPU 两个口径；区分「资源 Ready」与「首条命令完成」；再单变量优化，保留原始数据和分布（p50/p99），不拿平均值糊过去。
- 追问链：① wall 高但 CPU 低说明什么？② 缺页数能说明什么？③ 快照恢复的收益边界在哪？
- 要补的证据：一段真实的分段耗时表。

## B 区：广度速答（每题 15 秒，一句结论 + 一句原因）

| 题 | 一句话答案方向 |
|---|---|
| VirtIO 为什么比模拟真实设备快 | 数据走共享内存批量传输，只在有活时敲一次门铃，把 N 次 VM-Exit 压成 1 次 |
| ublk 是什么 | 内核把块请求交给用户态 daemon 处理，靠 io_uring 提交与完成交接，不是内核直接调 daemon 函数 |
| OverlayBD 是什么 | 把多个逻辑块层叠成一块虚拟盘 + 索引，供只读镜像与内存快照使用 |
| envd 是什么 | Guest 内的常驻服务，宿主经 TCP（tap0 + DNAT）下达执行命令、收 stdout 与退出码 |
| pause 做了什么 | 请求暂停并确认全部 vCPU 停下；与"内存已完成捕获/已持久化"不是同一节点 |
| 池化预热解决什么 | 省掉冷启动的部分阶段，但不免除恢复开销与首命令延迟 |
