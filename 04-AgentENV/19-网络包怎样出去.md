# 第 19 课：网络包怎样出去

2026-11-05。基线 `9f62cbe07cebfecf416dc9bdcf497e2a97687644`。本课阅读 docs/src/internals/networking.md，以及 slot.rs 的网络创建、SNAT/DNAT 规则与 manager.rs 的全局规则；VirtIO 部分沿用第 06 课的机制说明，未重新审计配套 Firecracker 网络实现，未做实际抓包或连通性实验。

## 1. 前置对象与位置

| 对象 | 位置和含义 |
|---|---|
| Guest eth0 | Guest 内核看到的虚拟网卡，由 VirtIO 前后端连接 |
| VirtIO-net 后端 | Host Firecracker 内的设备实现，处理 Guest 队列与 TAP 之间的数据 |
| TAP / tap0 | Host 内核虚拟以太网接口；用户态通过 fd 读写帧，衔接 Firecracker 与宿主网络栈 |
| network namespace | Host 内核划分的网络环境，分别维护接口、路由等；不是进程或另一台 VM |
| vpeer / veth-{slot} | 一对 Host 虚拟以太网接口；前者位于沙箱 netns，后者位于 Host 主 netns |
| 路由、过滤、NAT | 分别决定往哪转发、是否允许、怎样改写地址；三个问题不可混为一谈 |

Guest 内核的网络栈、Host 沙箱 netns 的网络栈环境、Host 主 netns 必须分开。后两者属于同一个 Host 内核。TAP、veth、netns 不是依次调用的三个用户进程。TAP 能接桥，但本课基线的所述路径通过 IP 路由转发，不应擅自画入 Linux bridge。

## 2. 位置图

```text
Guest：用户程序 → Guest TCP/IP → eth0 / VirtIO-net 驱动
                                ↕ virtqueue，buffer 在 Guest RAM
Host 用户态：             Firecracker VirtIO-net 后端
                                ↕ TAP fd
Host 沙箱 netns：              tap0
                                ↕ 路由、策略、NAT
                              vpeer
                                ↕ veth pair
Host 主 netns：              veth-{slot}
                                ↕ 路由、防火墙、NAT
                          出口接口 → 外部网络
```

出口接口不限定为裸机物理网卡，部署可能还有虚拟网络。图只说明普通路由出站分支，不代表域名代理分支中仍是同一条端到端 TCP 连接。

## 3. 发包与收包

课堂场景：Guest 向一个已知 IPv4 地址建立 TCP 连接，策略允许，未触发出口代理，暂不展开 DNS/ARP/分段卸载。

发送时 Guest 程序调用 socket API，Guest 内核组织网络数据；VirtIO 驱动将发送 buffer 的描述符链头发布到 TX 可用环，并在需要时通知。Firecracker 后端读取描述符，访问相应 Guest RAM，把帧交给 TAP。通知本身不携带包内容。

Firecracker 对 TAP fd 写入帧，从 Host 内核看是 tap0 收到一帧；Host 内核继续处理路由与过滤。TX 的 used 完成说明该发送缓冲可以按协议回收，不说明远端已收包或业务成功。普通 TCP send 返回也不等于远端业务成功。

返回时，Host 网络处理把帧发向 tap0，Firecracker 从 TAP fd 读取，使用 Guest 已发布到 RX 队列的可写 buffer，写入收到的数据并发布 used，按需通知 Guest；Guest 驱动/协议栈再处理。TX 与 RX 是不同队列，不能说发包与收包共用一个可用环。这里不推断每包固定复制次数或每包一次通知。

## 4. netns、veth 与地址转换

netns 提供不同网络视图，veth pair 为两个视图建立连接。每个 netns 都可有名为 tap0 的接口；配置也可以复用 Guest 地址，因为先由不同 netns 分隔，再用 slot 专属的外侧地址区分。

此基线普通出站路径中：

1. 沙箱 netns 将 Guest 源地址 SNAT 为 slot 的 host_interaction_ip。
2. 包经 vpeer/veth 到 Host 主 netns。
3. Host 对相应源地址段应用 MASQUERADE，使源地址适配出口。

SNAT 改源地址；DNAT 改目的地址；MASQUERADE 是依出口地址处理的源 NAT。源端口在需要时也可能被转换。不应把 NAT 当加密、权限隔离或必然的部署要求；这是此版本的实现选择。

返回流量依赖连接跟踪的 NAT 状态逆向还原，并经返回方向路由和 ESTABLISHED/RELATED 放行规则交付。不能理解为 server 每次读取包内容后决定收件 VM；不保证任意既有宿主规则、上游 ACL 与网络条件下都可连通。

## 5. Host 怎样访问 envd

Host server 访问 slot 的 host_interaction_ip:envd_port；Host 路由将流量经 veth 送进对应 netns，netns 的 PREROUTING DNAT 将该地址改成 Guest vm_ip，再经 tap0、Firecracker 和 VirtIO RX 到 Guest envd。

```text
server socket → Host路由/veth → vpeer → DNAT → tap0
→ Firecracker → Guest VirtIO RX → Guest TCP/IP → envd
```

这条宿主到 Guest 的 TCP 通道，与 server→Firecracker API 的 Unix socket 不同。普通 Guest 出站包通常由 Host 内核转发，不必经过 server 的 HTTP handler。

## 6. 策略与代理分支

有路由不表示允许访问。基线有内部地址池禁止规则和用户策略；namespace 隔离本身也不等于自动阻止全部网络连接。

需要代理介入的策略会把 TCP 80/443 REDIRECT 到该 netns 的出口代理监听 socket。代理检查 HTTP Host 或 TLS ClientHello SNI 等信息，再建立上游连接、转发字节；此基线文档声明不终止 TLS、不改写 HTTP。它不等于所有协议的通用域名防火墙，不能把 UDP 443 也算进 TCP 重定向。代理状态在 server 进程的注册表中管理，不应猜成每沙箱一个独立代理进程。

已有连接与新连接的策略效果不同。文档说明代理连接持有 accept 时的策略副本，现有转发不会因普通策略替换主动终止；不能用“更新 deny”推断全部已有 TCP 会话已断开。具体策略优先级后续安全课再展开。

## 7. 与快照恢复的联系

快照恢复可替换宿主 tap0 绑定并重新准备网络环境。恢复 Guest RAM 和 socket 状态不保证外部对端状态、Host conntrack/NAT 状态或网络超时一起回到过去；不能据此保证旧 TCP 连接继续可用。

## 8. 自测

1. Guest TX 描述符已经写入 used，能否说明外部服务已经收到请求并成功处理？为什么？
2. A、B 都有 Guest eth0 和 Host tap0，名字相同是否意味着共用一张网卡或一定冲突？需要区分哪些网络环境？
3. Guest RAM 中恢复了旧 TCP socket，是否足以保证原外部连接继续可用？请举一个没有一起恢复的状态。
