# 第 6 课：VirtIO 描述符、队列与通知

## 1. 描述符负责描述缓冲区

描述符告诉设备：Guest 提供的缓冲区在哪里、有多长、设备可以怎样访问，以及是否连接下一项。描述符本身不执行复制，也不规定底层必须采用某种复制方式。

| 字段 | 大小 | 含义 |
|---|---|---|
| addr | 64 位 | 本课未启用地址转换扩展的模型中，是缓冲区 GPA |
| len | 32 位 | 缓冲区长度 |
| flags | 16 位 | WRITE、NEXT 等标志 |
| next | 16 位 | 有 NEXT 标志时，下一描述符的表下标 |

一项共 16 字节；编号是表下标，不是额外字段。WRITE 从设备视角理解：允许设备向该缓冲区写入。描述符可串成链，描述多块不连续的缓冲区。

下面地址、编号和容量均为假设：

```text
可用环中的链头编号 1
          ↓
描述符 #1：addr = GPA 0x20000，len = 2048，flags = WRITE
          ↓
接收缓冲区：存放实际包字节
```

宿主软件设备不能直接把 GPA 当作本进程指针；需要经 Guest RAM 映射并验证范围等条件后访问相应内存。

## 2. 两个环记录交接进度

| 部分 | 作用 |
|---|---|
| 描述符表 | 描述缓冲区及其链关系 |
| 可用环 | Guest 发布可交给设备处理的描述符链头编号 |
| 已用环 | 设备发布已完成的链编号与实际写入长度等信息 |

以收包为例：

```text
Guest 准备接收缓冲区及描述符
    → 发布链头到可用环
    → 设备写入数据
    → 设备在已用环发布完成信息
    → Guest 处理数据
    → 缓冲区可复用时，再次发布到可用环
```

两次发布相同链头代表两次使用机会，不是同一个包发布两次。Guest 未处理完数据就交回缓冲区，设备可能覆盖仍需读取的内容。实际协议还要求正确的内存顺序与发布机制；本图不是完整并发实现。

## 3. 通知提醒对方检查队列

- Guest 发布可用项后，必要时通知设备。
- 设备发布完成项后，必要时通过虚拟中断通知 Guest。
- 请求和处理进度记录在队列里，通知不携带整个包。多项工作可以配合一次通知；通知抑制、轮询和处理预算等依具体实现。
- 条件变量只能类比“任务记录与提醒分开”，不能据此断言 VirtIO 实际使用条件变量。

纸面例子：可用环有链头 3、7、9，Guest 通知一次。设备检查队列后能发现多项工作，不应把通知次数当作请求数；调度及预算可以限制本轮处理数量。

## 4. 适用范围与快照的区别

VirtIO 是 Guest 驱动与虚拟设备协作的标准接口；并非所有设备都采用 VirtIO，也并非所有内存写入都经过它。

| 场景 | 本课 VirtIO 队列是否参与 |
|---|---|
| Guest 普通赋值或内核修改数据结构 | 不参与 |
| Guest 经 VirtIO 网卡、块设备进行 IO | 参与相应队列路径 |
| Firecracker 初始化时加载 Guest 内核 | 无需 Guest 先提供 VirtIO 接收队列 |
| AgentENV 宿主侧提取 RAM 保存快照 | 这条路径本身不依赖 Guest VirtIO 队列 |

用户提出的“保存 60 MB 内存到磁盘”沿此前讨论的 AgentENV 路径为：

```text
Firecracker Guest RAM 映射
    → process_vm_readv（远程 PID/HVA → server 本地缓冲区）
    → 快照写入逻辑
    → 宿主文件系统与存储
```

可以分批读取、写入，不要求一个完整 60 MB buffer。宿主存储驱动可能有自己的队列，那是另一层机制；文件写入成功也不自动等于已持久化到介质。

## 6. 环的记录、进度与复用

下面是 split virtqueue 的普通逐链完成示例，不涉及 IN_ORDER 批量完成优化。队列大小假设为 16：

```text
avail.ring[0] = 3
avail.ring[1] = 7
avail.ring[2] = 9
avail.idx     = 3       // 共发布三项，下一发布槽位是 3
设备消费位置 = 2       // 已领取前两项，剩链头 9 未领取
```

取走条目通常只推进消费位置，不清空槽位；槽位残留数字不表示新任务。索引是有限宽计数器，槽位按位置对队列大小取模；处理回绕要遵守协议，不能只作无限整数比较。

已用环每条记录是两个 32 位字段：id（完成链的链头编号）和 len（设备向可写缓冲区写入的字节数），不是缓冲区容量。设备完成链头 7 并写入 1000 字节时，可以先写 used.ring[0] = {id:7,len:1000}，按规定内存顺序发布 used.idx = 1，再必要时通知 Guest。Guest 用自己的已用环消费位置发现新完成项。

描述符表、可用环和已用环占不同、不重叠的字节区域；可以在一块大分配里分区，也可以按接口规则分开放置。实际数据缓冲区可以在其他 Guest 内存位置。

发布到 avail 后，Guest 按协议将缓冲区交设备使用；设备领取不等于完成，不能因此提前复用。收到 used 后，Guest 驱动检查结果、处理数据，确认能复用时再发布到 avail。交接是协议约定，不代表每次撤销页表映射。

## 7. 一次 VirtIO 块读取

典型 virtio-blk 读链包含设备可读的请求头（操作和磁盘扇区位置）、设备可写的数据缓冲区、设备可写的请求状态区域。队列描述的是整条链，不仅是一块收包 buffer。设备状态需检查；used.len 不能代替块请求的成功/失败状态。

Guest 内存的缓冲区地址与磁盘逻辑地址是不同字段。参考 [VirtIO 1.2](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html) 的 split virtqueue 与 Block Device 章节。
