# 第 14 课：快照状态与一致性

2026-11-03。关联：[第 13 课](13-mmap缺页与COW.md) · [学习记录](学习记录.md)。按整课讲解、课末自测。固定源码基线 `9f62cbe07cebfecf416dc9bdcf497e2a97687644`。

## 1. 一份可恢复状态的组成

| 部分 | 内容示例 | 不能替代什么 |
|---|---|---|
| VM 状态 | vCPU 寄存器、指令位置、虚拟设备状态 | 不是复制 RAM 就能自动得到 |
| 内存镜像 | Guest 内核、进程堆栈、页表、缓存等 RAM 内容；可由本层加父层组合 | 只保存 rootfs 不保留执行中的变量 |
| 磁盘视图 | 用户镜像、必要的额外盘及父层引用等 | 不能默认使用另一个时间点的可变磁盘 |
| 恢复配置和索引 | 各部分位置、层顺序、设备关联、兼容配置 | 单个文件存在不代表整套产物可用 |

磁盘只读基础层可以复用，无需每次完整复制；内存也可增量保存。所有必需引用仍须存在。VM 外部服务、宿主外部连接状态不自动被捕获。

## 2. 为什么需要一致性

纸面例子：真实内存从 x=100,y=100 按 x=90、y=110 顺序更新。采集者先读旧 x=100，更新结束后才读新 y=110，会拼出实际从未同时存在的 x=100,y=110。描述范围或记录脏页不冻结其内容。

暂停所有 vCPU 可以停止 Guest CPU 写入，但宿主设备侧仍可能写 Guest RAM。完整方案还需按实现协调设备、在途 IO 和状态捕获，不能仅凭低层 pause 一步就声称所有组件静止。

暂停若恰好发生在 x=90,y=100 的真实中间时刻，捕获该时刻不必是错误快照。这区分机器执行状态一致性与应用事务已提交：恢复可让应用继续执行剩余步骤，不保证暂停点正好是业务事务边界。

## 3. 固定版本的捕获主线

本轮实际读取 sandbox.rs 的 pause_to_dir、snapshot_to_dir、snapshot_memory_to_overlaybd：

```text
pause_to_dir
  → 若存在可写持久卷，经 envd 同步其文件系统
  → fc_instance.pause()
  → snapshot_to_dir
      → snapshot_memory_to_overlaybd
          → create_state_only_snapshot(vm_state_path)
          → get_dirty_memory_ranges()
          → convert_dirty_memory_to_overlaybd(Firecracker PID, 范围, ...)
      → 组合父内存层与本次层、写内存镜像配置
      → 捕获/封存所选磁盘后端状态，生成 manifest 与恢复配置
```

这是主线导航，省略额外盘、不同后端、错误恢复分支，并非所有步骤的完整时序证明。state-only 是该集成接口的语义，不推广到任意上游 Firecracker 发行版。设备内部 drain/暂停协议尚未逐函数核对。

文件系统同步不等于用户程序私有缓冲已 flush，也不等于外部数据库事务完成；存在可写持久卷时的预同步分支不可扩写成“所有应用都已静止”。内存数据采集与磁盘层都要匹配恢复时的状态。

## 4. 暂停、捕获、持久化、释放分开

- 原地暂停：停止继续执行，原运行时资源可以仍在。
- 捕获：生成 VM 状态、内存层、磁盘层与恢复配置。
- 持久化/发布：按接口和后端契约保存完整产物与引用，不能把普通文件 write 返回当作介质持久化。
- 释放运行时：关闭实例并回收资源，独立于文件是否存在；AgentENV 外层生命周期策略不可与低层 pause 混为一谈。

捕获函数中间可能已写出部分文件后失败；单个 vm_state.bin 或内存层成功不能代表整个快照成功。源码有失败目录清理和上层恢复逻辑，详细异常路径留第 23 课。

## 5. 恢复的两条路径与外部边界

原地 resume 可继续原有运行时；从快照重建则需重新准备运行时、关联磁盘、加载 VM 状态并映射内存镜像，再继续执行。按需加载意味着未预读全部页，不是遗漏所需逻辑状态。

快照内的“付款请求已发出、等待响应”不能回滚外部支付系统已完成的交易。恢复与重试仍需业务幂等、重连等协议。VM 内一致性、文件系统恢复能力和应用业务一致性不能互相替代。

## 6. 课末自测

1. RAM 保存完整，但没有 vCPU 指令位置和寄存器，是否足以继续原程序？为什么？
2. VM 状态文件已保存，内存层写入失败，是否能把本次快照标记为成功？
3. VM 恢复到“付款请求刚发出”的时刻，能否断言外部支付系统也回到了那个时刻？

2026-11-03 用户三题核心回答正确：缺运行上下文不能恢复；内存层失败不能标记成功；外部数据不随 VM 恢复。第二题表述已校准：VM 状态文件本身已成功，不完整的是包含 RAM 的整套快照。第一轮自测证据已记录，源码阅读与纸面推演不等于真实 microVM 一致性验证，尚待延迟迁移复习。
