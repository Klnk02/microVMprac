# 基于 AgentENV 吃透沙箱：逐课学习计划

制定日期：2026-10-23。

目标：能从进程、地址空间、调用关系、数据流和资源生命周期解释 AgentENV，独立追踪创建、执行、文件读写、暂停、恢复和销毁，并分析一种实现选择的收益与代价。

## 2. 用三张图理解系统

AgentENV 不是所有组件从上到下依次穿过的单一层栈。API 是接口，server/Firecracker/ublk daemon 是宿主进程，KVM/ublk driver 属于宿主内核，OverlayBD 是存储库与格式，envd 和用户程序在 Guest 内。不能把它们画成地位相同的一串进程。

按顺序建立三张图：

1. **位置图**：在哪台机器、哪个进程、Host 还是 Guest、用户态还是内核态。
2. **调用图**：谁请求谁，参数是什么，返回值和错误回到哪里。
3. **数据与资源图**：字节在哪里，发生了复制还是映射，谁持有和释放 buffer、fd、进程、设备与快照层。

第一张见 [系统地图与第一课](01-系统地图与第一课.md)。后两张随课程逐步补齐，不在第一天一次性塞满。

## 3. 每课如何进行

每课建议 20—40 分钟；以理解进展调整，一课必要时拆成多轮对话。

1. 提一个具体场景，只检查一个主要问题；先让用户说出自己的推理。
2. 明确区分：答对的部分、尚未说明的部分、具体错误；不把术语出现当作掌握。
3. 解释当前需要的 1—3 个概念；新名词给出中文含义与实际对象。
4. 画一张局部图，或读一小段源码，先标调用者、输入、输出、执行位置，再看实现。
5. 做一个纸面推演、C++ 风格伪代码练习或小实验；Rust 语法按需补，不要求先学完整语言。
6. 用户用自己的话复述，再换一个条件追问，确认能迁移理解。
7. 将答题证据和缺口写入 [学习记录](学习记录.md)。验收后再标记掌握；未作答时可继续准备材料，或在用户要求继续时解释一个相邻的小例子，但不把继续请求当作答题正确。

错误时只补当前依赖，不额外铺开整套内核知识。阶段末用新场景检查，不反复换措辞问同一题。

如果用户没有回答而要求继续，先解释上题的答案，再通过一个更具体的短例子推进；保留待检验状态。避免反复发送同一道题，也避免用批量生成材料替代逐步讲解。

当前本地是 Windows 学习库，读源码、画图和纸面实验可以直接进行；Linux/KVM 实验到对应课程再确认专用环境。未执行的实验只记为练习方案，不能标为验证完成。

## 4. 28 节课的具体安排

### A. 先站稳位置：第 1—3 课

| 课 | 核心问题 | 练习与验收 |
|---|---|---|
| 01 谁在哪里 | server、Firecracker、ublk daemon、envd、用户程序、KVM 分别是什么 | 自画 Host/Guest 位置图；说明 Firecracker 是宿主进程、Guest 内核由它借助 KVM 运行，不能把 Guest 进程当成宿主普通子进程 |
| 02 一个指针属于谁 | 同一数字地址为什么在两个进程里可能指向不同数据 | 用两张进程页表解释 `pwrite` 与 `process_vm_readv` 的参数；指出哪个参数描述本地地址，哪个指定远程进程 |
| 03 Guest 内存与宿主映射 | GVA、GPA、HVA、HPA 分别描述什么 | 分别画 Guest 访存的两阶段翻译与 Firecracker 的宿主访存；解释它们可以落到同一物理页，HVA 不是 Guest 硬件翻译必经的一环 |

材料：固定版本架构图、`instance.rs` 中的宿主进程创建与 PID、`process_vm_reader.rs` 中本地/远程 iovec。验收前只读这些相关片段。

### B. 虚拟机如何执行与访问设备：第 4—6 课

| 课 | 核心问题 | 练习与验收 |
|---|---|---|
| 04 谁在执行 Guest 指令 | vCPU 线程、KVM 与物理 CPU 如何配合 | 解释 `KVM_RUN` 和 VM-Exit；区分进入内核、进入 Guest 与普通线程切换 |
| 05 Firecracker 内部谁负责什么 | API、VMM、vCPU 线程如何分工 | 对“改配置、执行指令、处理设备请求”分别找到执行角色；不把 HTTP API 当作每次访存的通路 |
| 06 VirtIO 请求怎样传递 | 前端驱动、后端设备、队列、buffer、通知各是什么 | 用一次块读取画出描述符、可用/完成状态和通知；能解释队列也在内存里、轮询与通知各有取舍 |

材料：既有 Firecracker 笔记、官方设计与相关源码；Firecracker 自身的版本也需在具体源码课记录，不能默认上游最新版等于 AgentENV 使用版。

### C. 跟踪创建与命令执行：第 7—9 课

| 课 | 核心问题 | 练习与验收 |
|---|---|---|
| 07 一次请求到达哪里 | 客户端、节点 API、orchestrator、sandbox backend 如何衔接 | 画单机控制调用链；区分模块、trait、进程与通信接口 |
| 08 冷启动准备了什么 | 镜像、磁盘、网络、Firecracker、内核与就绪检测是什么关系 | 追踪 `start`/`start_nowait`/`wait_for_ready`；说明 API socket 就绪不等于 guest 服务可执行命令 |
| 09 `exec` 最终在哪里运行 | server、envd 与 Guest 进程谁接收和执行命令 | 跟踪一次简单命令与 stdout/exit code 返回；解释宿主看到的 PID 与 Guest PID 属于不同视角 |

材料：`src/api/`、`src/orchestrator/`、`backend.rs`、`sandbox.rs`、`instance.rs`、`src/sandbox/` 的 envd 与执行集成。具体 handler/函数到课时核验，不能由名称猜完整链路。

### D. 文件为什么变成块设备：第 10—12 课

| 课 | 核心问题 | 练习与验收 |
|---|---|---|
| 10 文件、文件系统与块设备 | Guest 的 `/tmp/a`、`/dev/vda` 与宿主镜像文件有何区别 | 分开画 Guest VFS/缓存和 Host 文件/缓存；解释 Guest 写入返回不证明宿主介质已持久化 |
| 11 OverlayBD 层和索引 | 多个文件怎样组成一个逻辑磁盘 | 用几段逻辑块手算新层覆盖父层、空洞与显式零记录；区分逻辑偏移与层文件实际位置 |
| 12 ublk 与存储 daemon | 内核块请求怎样交给用户态处理 | 画 Guest 文件读 → VirtIO → 宿主 ublk → daemon/OverlayBD → 后端的主路径；标出控制消息与数据读取，不预设固定复制次数 |

材料：架构文档的存储部分、`storage/overlaybd/`、`storage/ublk/`、`storage/ublk-daemon/`、`src/sandbox/ublk/`。每次只选一个本地后端读请求，远程下载在后续拓展。

### E. 内存、pause 与 resume：第 13—18 课

| 课 | 核心问题 | 练习与验收 |
|---|---|---|
| 13 mmap、缺页与 COW | 建立映射与真正复制字节有何区别 | 用两个实例共享同一快照页，再让一个实例写入，解释新旧页及拥有者；区分 Guest 缺页与宿主提供 Guest RAM 的缺页 |
| 14 快照要保存什么 | 寄存器/设备状态、RAM、rootfs 为什么要配套 | 用两页更新举例说明一致性；区分原地暂停、快照捕获、释放运行时，不把所有 pause 等同于释放内存 |
| 15 哪些页要保存 | dirty/present 范围、父层与内存镜像逻辑位置 | 手算一个小型增量内存镜像；解释页粒度不等于读取请求粒度，脏页列表不自动保证内容冻结 |
| 16 pause 的跨进程读取 | 谁调用 PVM，源和目的在哪 | 为每个参数标 PID、地址空间和长度；解释 chunk 先是任务集合，buffer 分配、复制、写出是不同动作；可判断短读/失败 |
| 17 chunk 写出与快照封存 | entry、chunk、writer、文件页缓存怎样相接 | 画 metadata 与 payload 两条线；说明 `async` 外壳不改变 PVM 同步实现，chunk 不自动合并 syscall；检查最终层的索引与文件位置 |
| 18 从快照 resume | 状态加载、只读内存设备、映射、按需加载与 COW 如何配合 | 分冷缓存/热缓存/首次写入追踪一页；区分 resume 返回和后续首次访问，不能把请求内存量当作实际物理读盘量 |

材料：`sandbox.rs`、`instance.rs`、`overlaybd_snapshot.rs`、`process_vm_reader.rs`、`helper.rs`、`virtual_file.rs`。先沿原生实现讲清，再把 DSA 实验作为应用题。

### F. 网络、隔离与资源：第 19—21 课

| 课 | 核心问题 | 练习与验收 |
|---|---|---|
| 19 一个网络包怎样出去 | Guest 网卡、VirtIO、TAP、netns 与宿主网络各在哪 | 跟踪一个出站请求和回包；实际路由、NAT、过滤规则随配置核验，不把某张通用图当作所有部署事实 |
| 20 各种隔离分别限制什么 | KVM、权限、namespace、cgroup、seccomp 各控制哪一部分 | 对“Guest 任意 syscall、VMM 被攻破、CPU 超用、网络外连”分别找控制点；区分安全设计建议与实际启动配置 |
| 21 谁拥有与回收资源 | 进程、fd、TAP、ublk、快照文件由谁管理 | 为一次创建/销毁列拥有者与释放条件；分析中途失败可能遗留什么，不能把引用消失等同于所有资源已安全回收 |

材料：`src/sandbox/network/`、`resources.rs`、`pool.rs`、`src/sandbox/ublk/` 与 Firecracker 对应安全文档；从本次学习基线找实际创建和清理分支。

### G. 并发、可靠性与观测：第 22—24 课

| 课 | 核心问题 | 练习与验收 |
|---|---|---|
| 22 async 到底让出了什么 | Future、Tokio worker、阻塞 syscall、io_uring 如何区分 | 用单 worker 时间线判断两个任务能否交替；解释 buffer 必须活到实际 IO 完成，并区分异步与多线程/并行 |
| 23 失败与恢复 | Pausing/Paused/Resuming 等状态为何不能随意跳转 | 选一次快照写失败与一次恢复失败追踪状态、原运行时、临时文件和错误；讨论重试、取消与幂等 |
| 24 性能指标怎样读 | wall、onCPU、缺页、缓存命中、吞吐分别说明什么 | 对已有一组实验解释测量边界，列证据/推断/未知；定位慢在哪一段，不能把 copy 采样比例当可卸载收益 |

材料：orchestrator 状态与 persistence、`storage/util/` IO 抽象、现有 DSA 实验状态记录。汇总数据只证明已声明范围；未拿到原始数据时不伪称复核完成。

### H. 从单机扩展到平台：第 25—26 课

| 课 | 核心问题 | 练习与验收 |
|---|---|---|
| 25 多节点与资源池 | gateway、scheduler、节点 server 如何协同 | 画请求选节点和落到节点后的边界；分清空闲网络/进程/块设备池，解释预热没有自动免除所有恢复开销 |
| 26 模板、持久化、fork 与 Agent 状态 | 快照在本地、仓库和运行时缓存中怎样流转 | 区分临时产物、持久化记录、模板和运行时缓存；说明 fork 的共享与私有内容，并解释 VM 状态不等于完整外部 Agent 任务状态 |

材料：`services/`、`src/snapshot/`、`src/template/`、持久化产物说明。跨节点对象存储、镜像传输与本地缓存必须分段描述。

### I. 综合掌握：第 27—28 课

| 课 | 核心问题 | 练习与验收 |
|---|---|---|
| 27 端到端复述与排障 | 能否从请求追到硬件，再回到结果 | 独立画创建、exec、文件读、pause、resume、销毁六条链，任选两条用代码和观测交叉印证 |
| 28 实现取舍与迁移 | 能否提出改法并说明边界 | 比较现有 PVM 中转与 Firecracker 直接写出；列所省复制、仍有成本、格式/一致性/接口改动和验证方法；再设计一个小型执行服务的最小边界 |

不要求在学完前独立实现完整 AgentENV，也不以一定得到性能提升为毕业条件。理解负结果、找到证据不足之处，同样属于正确工程判断。

## 5. 节奏与复习

建议每周 2—3 课，另做一次约 20 分钟复习。28 课约需 10—14 周；这是安排参考，遇到缺口会拆课或回补。

- 第 1—3 周：A/B/C，先能讲清谁在哪里、虚拟机执行与创建/exec。
- 第 4—5 周：D，沿文件路径理解存储抽象，必要时延长。
- 第 6—8 周：E，用较多时间贯通 pause/resume。
- 第 9—10 周：F/G，补网络、安全、并发、失败与观测。
- 第 11—14 周：H/I、综合复习与遗留问题；前期较快时可提前。

课后约 1 天、1 周、阶段末各做一次简短回忆。每次复习换情境：改变调用者进程、冷热缓存、是否发生写入或是否中途失败，检查推理能否迁移。

## 6. 掌握标准与记录规则

每课使用四种状态：未开始 → 学习中 → 待复习 → 已掌握。还有缺口时保持学习中；隔一段时间仍能解释并完成迁移题，才标记已掌握。

每课需留下：

- 用户自己的解释或答题要点。
- 对进程/地址空间/调用/数据变化/完成条件的正确定位。
- 至少一份源码片段、局部图、纸面推演或实际观测。
- 教师指出的错误，以及用户后续修正。
- 一道换条件的题及结果；纸面题与真实实验分开记录。

整体达标还要求：能独立完成第 27—28 课；关键基础不再混淆；尚未验证的实现行为明确列出。没有用户答题与实践证据时，课程和长期学习目标都保持未完成。
