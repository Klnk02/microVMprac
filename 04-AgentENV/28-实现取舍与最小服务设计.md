# 第28课：实现取舍与最小服务设计

2026-11-16 第一轮。以既有第16—17课核对的AgentENV `9f62cbe07cebfecf416dc9bdcf497e2a97687644` 捕获链为基准，讨论设计候选，无实现修改或基准测试。本轮另核对Linux PVM/pwrite手册与Firecracker v1.10.1快照文档，仅证明上游快照文件接口，不视为AgentENV配套版本。

## 1. 地址翻译并不阻止FC自己写出

原路径：FC中Guest RAM宿主映射 → PVM跨进程读取 → server buffer → writer → 层文件。

候选：FC使用自己的HVA → pwrite/写出逻辑 → 目的文件。其buf按调用者FC地址空间解释，不需要先向server复制才可调用写文件接口。普通pwrite仍可能短写，返回成功不保证持久化。

```cpp
// 仅示意直接导出某段RAM到逻辑镜像位置，非完整快照或OverlayBD实现
write_all_at(fd, fc_hva, length, ram_image_offset);
```

这可以避免server侧的PVM payload中转，但不证明端到端零拷贝、零buffer或零内核成本。普通缓冲文件写入通常仍有复制，具体路径依IO模式。

## 2. 可恢复原始内存文件与项目层格式不同

Guest RAM字节保存下来，还要保留VM状态、内存布局、磁盘视图、父引用与恢复配置。AgentENV当前捕获还承担稀疏范围组织、逻辑offset到紧凑payload映射、索引/压缩等writer职责，不能只替换成一条裸write就假设输出兼容。

方案A：FC先导出普通RAM快照文件，server再转换为OverlayBD。可降低对FC的格式耦合，但新增中间文件及再次读取，可能抵消收益。

方案B：FC直接生成目标层或承担相应写出协议。可避免这次server中转，但需明确格式/接口、writer依赖、错误与进度报告、安全权限和版本维护。为什么原作者采用当前边界，若无明确设计记录只能作为推断，不能声称必因安全/性能。

## 3. 不能省略的一致性和寿命约束

需要稳定RAM视图、完整覆盖CPU/设备写入、正确跟踪周期、在途IO完成前维持源页与buffer寿命。直接写出不代表可以让Guest随意边改边保存；普通并发读取可能拼出不一致状态。若需提前resume，要引入真正冻结视图的额外机制并验证其开销。

写出放入FC时也要选合适线程/任务。若长同步写占住设备事件处理线程可能影响后端推进，不等于“改成async”就自动让出工作线程。还需处理取消、ENOSPC、部分文件、格式失败及完整快照发布。

## 4. 较小范围的候选：批量PVM

相邻源/目的范围可考虑合并，同一目标PID下离散范围可利用多个iovec。减少调用不等于减少payload复制，仍需IOV_MAX、短读跨段进度、长度/地址溢出及逻辑映射。与改FC直接输出相比，这是另一种改动范围与收益假设，不能未测就排序优劣。

## 5. 如何验证

先固定目标：保持可恢复性和持久化语义，比较pause确认到完整快照发布的wall、各组件总CPU、输出量和恢复正确性。可单独报告捕获阶段，不与完整暂停时间混为一谈。

固定Guest状态、脏页集合、快照链、压缩/格式、缓存与并发等。分开测范围准备、PVM或直接导出、格式写出/压缩、同步/发布。将server与FC等实际参与组件纳入同一计量范围，防止CPU成本仅从一个进程搬到另一个。

假设原总wall10ms，PVM2ms。即使2ms完全消失且无新成本，总wall也只到8ms，下降20%，不是减少一次搬运就减半。真实并行阶段需看关键路径，不能任意相加wall。

正确性需实际恢复对照RAM/磁盘内容，覆盖不连续范围、显式零、父层回落、短读/短写、源退出、ENOSPC、取消与发布失败。这里只列验证方案，未执行实验。

## 6. 迁移到小型执行服务

小服务至少明确：身份/权限与请求校验、实例ID到运行时的归属、后端start/exec/stop及其完成条件、超时取消与在途资源管理、按依赖清理与状态对账、阶段观测。不是把HTTP接口包在system命令外面就自动获得隔离和可靠性。

学习实现可先单机、单后端和受限命令，用状态与失败场景理解边界，再按实际需求增加快照与多节点。此为设计练习，无部署或开放服务。真实执行隔离、安全和持久化能力必须由所用运行时与配置验证。
