# 第 2 课实验：同一个地址，谁在调用？

关联：[第 2 课](../02-指针属于谁.md) · [学习记录](../学习记录.md)

## 它验证什么

两个普通 Linux 进程充当课堂角色：父进程模拟 server，子进程模拟 Firecracker。这里没有真实 Guest、KVM、AgentENV，也不启动或修改服务。

用私有内存映射和 fork，让两个进程保留相同的虚拟地址；随后子进程修改自己的内容。目标文件使用匿名 memfd，仅用于验证 pwrite 的源地址解释，不测试磁盘性能或持久化。

程序通过 Python 标准库和 ctypes 调用 Linux 的实际 libc 接口，无需额外 Python 包、C++ 编译器或 root。课堂上只需要理解下面三个操作，不要求先读懂全部 Python。

## 先预测，再看输出

已知父进程同址处内容是 `SERVER_PARENT`，子进程同址处内容是 `CHILD_GUEST_DATA`。

| 操作 | 哪个进程调用 | 写出的内容，先自己预测 |
|---|---|---|
| 把相同 VA 数字直接传给 pwrite | 父进程 | 待填 |
| 先指定子 PID 做 PVM，再写接收 buffer | 父进程 | 待填 |
| 用自己的源地址直接 pwrite | 子进程 | 待填 |

## 如何运行

在 64 位 Linux 中：

```sh
python3 02_address_spaces.py
```

当前 Windows 学习库可从 PowerShell 调用本地 WSL：

```powershell
wsl -d Ubuntu-24.04 -- python3 /mnt/d/learning/Learning/microVMprac/04-AgentENV/实验/02_address_spaces.py
```

输出的 PID 和地址每次可能不同，不能把示例值写死。程序等待子进程就绪后才读取，并在完成或失败后回收子进程与临时资源。

## 输出怎样解释

- `parent_virtual_address == child_virtual_address`：仅说明数字相同。
- `parent_pwrite_using_same_va_number`：检查父进程普通写入读取的是谁的数据。
- `parent_pvm_then_pwrite`：检查显式远程读取后的内容。
- `child_pwrite_using_its_own_va`：检查改变调用者后，普通写入的数据源。

脚本检查具体返回字节数和三份内容，不仅打印 PASS 字样。结果表明的是本轮两个进程的地址解释与数据传递，不证明任何特定 HPA/PFN 数值，也不证明 AgentENV 生产路径的格式正确、性能或全部恢复状态。

## 运行后只解释一件事

同一个虚拟地址数字为何在父进程和子进程的 pwrite 中读出了不同内容？先用“调用者的地址空间”解释，再把父/子替换成 server/Firecracker。

扩展问题留到后面：子进程直接写入虽能避免 PVM 中转，实际快照为何还要处理层格式、索引、源冻结和错误？这属于后续快照与架构取舍课程。
