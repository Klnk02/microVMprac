# 硬件隔离 vs 软件隔离

承前：内存隔离靠硬件（页表 + MMU），但还有很多隔离不靠硬件。

## 两条腿

### 硬件隔离（CPU 强制执行）

- 特权级：ring0 / ring3，靠 CPL，管「能不能执行特权指令、碰高权限内存」。
- 内存：每进程一套页表 + MMU 翻译，天然隔离。
- 特点：由硬件直接保证，进程绕不过去。

### 软件隔离（内核代码的数据结构）

- 文件描述符表、信号、主机名、挂载点、进程树… 都住在内核维护的数据结构里（如 `task_struct`、namespace）。
- 特点：本质上只是内核代码的「约定」。进程 A 拿不到 B 的 fd，是因为内核查表时按「你属于哪个进程」来给结果，没有硬件强制的墙。

## 对比

| | 硬件隔离 | 软件隔离 |
|---|---|---|
| 谁在保证 | CPU / MMU | 内核代码 |
| 典型对象 | 内存、CPU 特权级 | fd、信号、主机名、挂载点、进程树 |
| 强度 | 强，进程绕不过 | 靠内核逻辑正确 |
| 开销 | 相对高（页表、切换） | 轻、灵活 |

## 通向虚拟化的分野

- 容器（Docker）：主要靠**软件隔离**（namespace + cgroup），共享一个宿主机内核 → 轻、快。
- 虚拟机（VM）：主要靠**硬件隔离**（完整虚拟硬件 + 独立内核）→ 强、重、慢。
- Firecracker：两者组合——用硬件虚拟化（KVM）做 CPU/内存强隔离，用软件手段（seccomp / chroot / cgroup）收口。

> [!note] fd 精确说法
> 文件描述符是一个**整数下标**，索引进「每进程的文件描述符表」，表项指向打开的文件描述（file object）→ inode。它是内核数据结构，不是指针，也不是页表里的东西。
