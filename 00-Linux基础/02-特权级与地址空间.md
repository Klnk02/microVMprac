# 特权级与地址空间

两个**正交**的维度，不要焊在一起。

![[特权级与地址空间.svg]]

## 维度一：特权级（CPU 的「身份」）

- 记在 CS 寄存器低 2 位，叫 CPL（见 [[术语表]]）。
- `3` = ring3 用户态，`0` = ring0 内核态。
- 决定「你够不够格执行**特权指令**、碰**高权限内存**」。

特权指令举例：`cli`（关中断）、`lgdt`、`in/out`、`mov cr3`。它们改的是**系统全局状态**，绝不能给用户态。

## 维度二：地址空间（内存的「墙」）

- 由页表 + MMU 实现，是「虚拟地址 → 物理地址」的翻译表。
- 每个进程一套页表，所以天然隔离；每页带 U/S 位（`0` = 仅内核，`1` = 用户可访问）。

## 汇合点

内存访问那一瞬间，MMU 拿 **CPL** 去比页表项的 **U/S 位**：
用户（CPL=3）访问内核页（U/S=0）→ 拒绝，抛异常。

所以「内核态 / 用户态」的本质是**特权级**，不是「地址隔离」。

## 特权指令为什么必须存在

时钟中断是内核**夺回 CPU 控制权的唯一保证**：进程被抢占、时间片调度，全靠它周期性把 CPU 交回内核。

- 用户进程执行 `cli` 关中断 → 进入 `while(1);` 死循环，且不再发系统调用。
- 此时内核**再也无法**夺回 CPU —— 整个系统卡死（拒绝服务 DoS）。

所以「能不能关中断」必须是一个**特权**问题。特权指令改的都是**全局控制状态**：`cli`（关中断）、`lgdt`（改描述符表）、`mov cr3`（换页表）、`in/out`（直接碰硬件）。玩家不能改规则，只有裁判（内核）能改 —— 这就是 ring0 / ring3 存在的意义。

> [!note] 伏笔
> 这套「特权级 + 特权指令」机制，正是硬件虚拟化（VT-x）要操纵的对象。guest 内核以为自己跑在 ring0，其实已被剥夺特权；它一旦执行特权指令，CPU 不会照做，而是「陷阱」到 hypervisor —— 这就是 VM-Exit 的雏形。
